# Universal development and documentation workflow

Applies to every developer, automation and agent, from implementation through tests, edits, revisions and interrupted work. Scope X06/DOC-01 requires current documentation; X07/DOC-02 requires uniform change history. The original 548 requirements keep their IDs, optional flags and acceptance gates. A task cannot be reported finalized with missing evidence or an undocumented current behavior.

## Intake and checkpoint

1. Read AGENTS.md, this file, [current handoff](HANDOFF.md), relevant feature documents and task/requirement registers. Read the full blueprint and original checklist before product work. Inspect branch, HEAD, remote and dirty files before editing. Preserve other work and private environment/data.
2. Discover the actual Dev Container/Compose project and execute application commands there. Do not infer access or current listeners from an old handoff. Record toolchain and access limits; request only genuinely blocking access or Director decisions.
3. Select a scoped branch; keep concurrent work isolated. Create the next `CHG-YYYYMMDD-NNN` JSON record using [the format](CHANGELOG_FORMAT.md). Start as `draft`, with current UTC `recorded_at`; set `occurred_at` only when supported by evidence. Record actor, task/requirement/feature IDs, changes, files, impacted docs, intended checks and limitations. Never infer a test timestamp from a file modification time.
4. At meaningful implementation/test checkpoints, update the draft's changes, document reviews and verification references, then synchronize the snapshot. On interruption set `interrupted` or `blocked`, record what actually ran and update the handoff. Start a new record on resumption of a sealed entry. Do not silently erase failed attempts.

## Implement and maintain documentation together

Consult [documentation-map.json](documentation-map.json) before a change. For every affected source, review every mapped current document; record `updated`, `reviewed_unchanged` with a concrete reason, or `historical_preserved` for immutable provenance. Add missing impact edges and classify every new document. Re-evaluate the map when package boundaries or public behavior changes. Automatic path/hash checks support this review; a human/agent must check semantic accuracy.

Describe callable behavior at its owning feature/package: inputs, outputs, errors, state transitions, lifecycle, authority and limitations where relevant. [FEATURES.md](FEATURES.md) names the foundation interfaces. The generated callable inventory records all project-owned JS/TS declarations, methods, getters and callbacks, and Python definitions/lambdas with file/line/signature. It is observed inventory, not invented function creation history. Change records link affected files/features to timestamps; Git supplies exact diffs. Non-callable CSS/config/build behavior is recorded by file hashes and feature ownership.

Update task status and requirement evidence without accepting a product requirement from partial infrastructure proof. An implemented feature can remain pending verification. Before synchronizing an executable-source change, mark verification entries with an obsolete whole-source fingerprint pending and retain their prior evidence references. Generate a consistent draft snapshot, run the appropriate fresh checks, then restore verified status only with matching current evidence. The conservative whole-source gate prevents stale pass claims across workspace/config/test/schema changes. Keep ordinary Lab, Collection Play and manipulated Sandbox policies separate when those features appear. Add an ADR for material architecture changes with comparative evidence and affected IDs.

## Prove the change

Use meaningful checks for the actual change. Run the relevant doctor/configuration/bootstrap/database baseline and ordered application checks. Keep static, container execution, simulation, headless browser, real device, historical report and production evidence distinct. Human-only device observations use the explicit reported/manual convention in the record format, with no invented process exit. Device names and GPU conditions belong in evidence; viewport emulation is not real phone acceptance.

Capture commands inside the container with the [evidence recorder](CHANGELOG_FORMAT.md). It records source commit plus content fingerprint, exact start/end UTC, environment versions, exit status/signal, outcome and sanitized output digest. Do not pass secrets in command arguments or intentionally print them. Review logs before committing: redaction covers inherited named secrets, owned bootstrap/managed values read before and after execution, PostgreSQL URI passwords and private keys, not every possible unknown application secret.

Record every relevant successful and unsuccessful verification attempt. Historical imports use `reported`, null execution times and an explicitly supported source identity. `passed` requires captured execution with unchanged source and matching log digest. A later source edit invalidates current whole-source verification; rerun affected checks against the final source. Documentation-only edits require documentation validation and semantic review rather than repeating unrelated application tests.

## Close and hand off

1. Review all affected docs against code and task/requirement/feature status; update [HANDOFF.md](HANDOFF.md). Include branch/source, dirty work, listeners, exact checks/results, unresolved limits and concrete next steps. Use [the handoff template](templates/handoff.md).
2. Add run references, set the draft to `finalized` only when its scoped acceptance is satisfied, and record remaining external/device gates explicitly. Finalized tooling work can coexist with pending Windows product acceptance.
3. Run `pnpm docs:sync --change CHG-YYYYMMDD-NNN`, then `pnpm docs:check` and appropriate final checks. These reject stale file/function snapshots, unclassified/missing docs, broken local current links, unsupported passing claims and changed sealed records. Review the staged diff and secrets before a coherent commit. Use `git diff --cached --check -- . ":(exclude)docs/validation/logs/**"` for source/document formatting; captured tool logs preserve original whitespace and are checked by digests, not rewritten for style. Keep project-owned text in LF as required by `.gitattributes`; inherited CRLF checkout bytes must be normalized without changing register values before hashing. Preserve explicitly labeled archive provenance. Validate canonical Git checkout bytes as well as the live source copy; both must pass the same checks.
4. Give the Director a self-contained result: branch/commit, behavior, checks by evidence category, unresolved acceptance and next work. Never claim total gameplay/device/production acceptance from local foundation tests.

Run records and committed non-draft change records are append-only against their earliest available history in the current branch ancestry. Add a correction entry referencing the original rather than editing history. The source snapshot and Markdown changelog are generated and editable only through synchronization. Evidence/history directories avoid self-referential file hashes; their schemas, log digests and Git sealing are checked independently. SHA-256 proves identity, not correctness or authorship. BOOT-03 runs these same gates with full Git ancestry in the isolated pipeline; hosted execution/required-check enforcement remain unverified. Local gates remain mandatory.

`pnpm verify:clean` copies the audited project-owned source to a temporary directory, excluding credentials/Git/dependencies/build output, then performs a frozen install and complete foundation validation. It removes the temporary copy on exit and never connects to or recreates the existing database. Stop fixed-port development first. After checks, confirm actual owned listeners/process groups stopped; a suite exit alone does not prove cleanup. Diagnose and retain ownership before stopping leftovers. Capture it as container evidence; this is a source-only clean-checkout proof, not device or image qualification.

BOOT-02 current implementation/verification is recorded in [the database runbook](runbooks/database.md) and [validation](validation/boot-02.md). The original bootstrap administrator is separate from managed app credentials; normal clean foundation checks need no private DB. Actual integration/recreation checks are explicit and must retain their own source/timestamp/results.

BOOT-03 pipeline operation is in [the CI runbook](runbooks/ci.md). Use the WSL/Linux host launcher for an isolated image/database proof; application commands execute inside the fresh container. Result artifacts are ignored generated output, separate from durable run receipts and append-only changelog. Do not infer hosted execution or publish artifacts from an unsuccessful pipeline.
