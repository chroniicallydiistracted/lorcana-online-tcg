## Agreed behavior and scope

Use the pinned engine's existing **dynamic replenishing countdown**, with configurable initial time, maximum time, additions after successful actions and turn passes, and replenishment after an expired turn. On expiry the server passes the turn when legal. Use an already-defined legal default when available; otherwise pause for audited recovery. Repeated timeouts do not authorize a loss, concession or player-selected winner. Infrastructure outages and unreliable time also pause for audited recovery. Ordinary player disconnects and browser suspension do not pause the clock or replenish time.

Ink, ink drops, readying, turn legality, mandatory actions, choices and win conditions remain engine-owned. No upstream runtime/rules modification is proposed. A discovered defect must have a focused reproducer and repair review before changing upstream code. Changes to the project-owned bridge expose existing engine functions and remain behind the server adapter; they are not new card rules.

This is synthetic, two-player technical qualification under PLAY-01/02/03 authority. AUTH-01 stays separate with injected authenticated test sessions. All official-card, ordinary Lab/Collection, competitive/economic rewards, observer/private replay, multiplayer, real-device/load and production admission gates remain closed. No host clock repair, provider, Redis dependency, spending, deployment or startup-supervisor test change is included. Preserve all 548 requirements and their optional flags.

Affected acceptance: PLAY-04; R02.030/.031, R29.006/.007, R30.010; documentation DOC-01/02. Tournament round scheduling under R18.006 remains separate from a player's thinking-time clock.

## Existing implementation and reuse evidence

At the pinned `6de59de1` source, `core/runtime/types.ts` defines none/chess/priority/dynamic modes. `time-control.ts` supplies settlement, pause, resume, bonuses, timeout classification and skip replenishment. `match-runtime.init.ts` initializes players and starts pre-game thinking time. `match-runtime.commands.ts` follows the decision-maker, charges elapsed time, replenishes an outgoing exhausted player and awards dynamic action/turn bonuses. Pending choices can therefore move the running clock to someone other than the turn owner.

The exported upstream dynamic defaults are 150,000 ms initial/cap, +5,000 ms per successful action, +60,000 ms per pass, 60,000 ms reset after exhaustion, zero grace. These are source facts, not a production-duration decision. The existing command path can combine reset and bonuses: an exhausted player passing a normal turn can finish with 125,000 ms under those values. Tests must preserve that actual calculation rather than impose an independently invented reset rule.

`checkTimeout` classifies first/second incidents; `handleReserveExpiry` and one priority-mode fallback can award a loss. `clock-view.ts` has skip/drop affordances. Those are optional upstream mechanisms, not permission to enable them here. The selected policy must never translate a second incident into a loss or expose a client-controlled drop/forfeit operation. `passPriority` alone does not end a Lorcana turn; expiry must use validated `passTurn`.

The project-owned `vendor/tcg-engines/src/kernel.ts` currently supplies no `timeControl`, so the qualified application currently uses `none`. Existing persisted timestamps do not establish running timers, durable deadlines or a timeout scheduler. RUN-20261015-023 freshly passes all 37 unchanged selected upstream test files: 406 passed, one inherited skip, zero failed. This includes the existing timer and clock-view suites. It does not qualify the proposed integration.

## Alternatives

| Approach | Consequence |
|---|---|
| Reuse dynamic engine clocks through the adapter; add durable server scheduling | Recommended and Director-selected. Preserves tested engine replenishment and decision responsibility; adds the missing persistence, authority and recovery layer. |
| Implement an independent timer calculation in the service | Duplicates engine behavior and risks drift in bonuses, pending-choice responsibility and reconstruction. Rejected. |
| Enable upstream loss/skip/drop behavior as a complete transport policy | Does not satisfy the selected automatic legal turn pass and pause policy; upstream helpers do not supply durable multi-instance authority. Rejected. |

## Adapter, engine time and private reconstruction

Add a closed server-owned clock policy to timed synthetic setup. Validate bounded integer milliseconds, a positive initial/reset allowance, initial time no greater than cap, and bounded nonnegative bonuses. Qualification fixtures explicitly supply their values. Record the immutable policy and its version in the private transcript; never accept it from an ordinary player move. Untimed fixtures and the existing allowlist remain supported.

Extend only the project bridge/adapter with closed clock inspection and typed clock controls, using the upstream settlement/pause/resume helpers. Preserve runtime event/log sequence and history when replacing clock state through the existing `createRuntimeSnapshot`/`restoreState` APIs; using `loadState` would erase published history and is unsuitable. Reject or restore failed transitions without retaining the upstream pre-validation clock mutation. Invalid requests must still consume real thinking time through the persisted anchor; rejecting a move cannot grant time.

Keep engine timestamps as captured deterministic logical time. Persist a separate UTC anchor and map healthy elapsed thinking time onto the engine timeline. This lets a timely accepted move stop charging its player while the bounded engine computation runs. A successful commit starts the next waiting interval at the database authority's current time. The actual UTC event/admission time stays distinct from logical engine time in durable audit metadata. A rejected/abandoned calculation does not reset the anchor or earn a bonus.

Clock-only pause/resume/control records belong to the bounded private transcript and are re-executed during restore. They must reproduce both state and clock hashes, retain RNG outcomes and completion freeze, and reject altered policy, time, operation, outcome or ordering. New executable identities do not reinterpret old private checkpoints. Preserve existing data and retained manifests; unsupported old engine pins stay explicitly unavailable until a separately qualified retained loader exists.

## Durable state, action admission and timeout authority

Append migration0005; do not edit migrations0001–0004. The match role alone accesses the new clock/reservation/audit state. Store policy identity, remaining-time checkpoint, UTC anchor/deadline, engine timestamp, clock revision, paused/running/processing/ended status and bounded health/reservation metadata. Store a digest bound to private checkpoint/policy and verify reconstructed engine clock values, not just a mutable checksum. No seed/private card details go into clock audit, receipts, outbox or NOTIFY.

Use short row-locked transactions to reserve a timed transition against both committed engine version and clock revision. The database authority captures admission time and checks the deadline. A player reservation admitted strictly before the deadline wins against a later timeout. At the exact deadline or after it, the timeout path has precedence. Client timestamps and process scheduling do not decide this. An early valid request is not made late by subsequent engine computation. Retries still check their original durable receipt first, including after the refs have expired.

A reservation is database-fenced, bounded and uniquely owned. No transaction remains open during engine computation. Successful completion commits the candidate, clock state, receipt, journal/outbox and release pins atomically. Failure releases only the owned reservation and grants no time. A dead/expired owner causes a durable recovery pause, not a late player move, an automatic timeout loss or uncontrolled lease takeover. Other instances cannot commit a candidate from an obsolete reservation/version. Invalid-request floods cannot hold successive reservations beyond the configured request/work limits or freeze a player's time.

Timeouts use a dedicated internal operation, not the public player-command parser. It restores the exact committed state, checks the responsible player and deadline, and submits ordinary validated `passTurn` through the adapter only when legal. System receipts have a namespace/identity disjoint from either participant, so a client cannot preclaim a predictable timeout ID. Duplicate schedulers must return the same committed system outcome; losing candidates cannot alter time, RNG, events or winner. Engine validation remains mandatory. Preserve the existing single terminal-event invariant for natural completions and concessions.

Do not invent automatic choices of cards, targets, quest/challenge order or starting player. The initial default registry contains a legal turn pass and any independently verified no-choice defaults documented in the implementation; unsupported setup, unresolved effects and mandatory actions pause with a generic public reason. Adding a substantive choice policy requires Director review. This is deliberately bounded by current synthetic admission, not a claim of all-card timeout support.

## Time health, disconnects and audited recovery

Use PostgreSQL `clock_timestamp()` for shared durable UTC samples. Compare successive samples with the process monotonic clock and bound gaps, backward steps and disagreement. Thresholds are explicit operational configuration and covered by fake-time tests; this is not an external UTC certification. No browser calendar value enters authority. Consistent absolute UTC still depends on the deployment time source; the previous local clock investigation remains closed.

A bounded match-service clock runner reconciles all admitted timed matches, including those with no connected browser. Its health heartbeat distinguishes a routine idle game from absent infrastructure. If the maximum healthy interval is exceeded, a process restarts without a qualified continuity proof, or time samples become unreliable, pause at the last trustworthy charged point. Multiple live runners must not pause healthy work merely because one process restarted; database-fenced health/reservations are authoritative. Infrastructure failure cannot silently turn into player abandonment.

Pause and audited resume are explicit durable operations with a reason, audit identity, expected engine/clock versions, idempotency identity and recorded UTC. Resume reanchors the remaining allowance without silently charging the outage, refilling a player or settling a winner. Any compensating reset must be an explicit audited decision, never a reconnect side effect. There is no unauthenticated recovery endpoint or ordinary-player pause/resume tool. Actual administrative authorization/UI remains an AUTH/OPS admission gate; qualification injects a trusted internal audit authority.

The runner has a bounded scan batch, bounded concurrent work, no overlapping sweep in one instance, retry/backoff and explicit start/drain/close ownership. Shutdown cancels scheduling and waits for owned reservations/workers; a crash is recovered from database state. The existing worker app gains no public ingress. The original single-heavy-workload rule remains in force.

## Public protocol and browser behavior

Keep diagnostic1 and live2 schemas/handlers intact. Add a distinct live3 contract for timed matches and advertise built protocol1..3 only after its codecs/handlers are implemented and verified. Untimed matches can retain2; timed matches pin3. Select a ticket protocol that both the requesting client and the saved match actually support. Extend transport storage constraints additively for3; do not silently reinterpret a saved2 ticket/frame. Reconnecting old clients receive an explicit supported-version refusal for a timed match.

Keep viewer DTO revision1 intact. Live3 carries a separate closed public clock projection: policy identity, engine version, clock revision, server sample time, running/paused/processing/ended state, active participant, bounded remaining allowances, UTC deadline and generic pause reason. Never send raw `ctx.time`, private state/RNG, server reservation capabilities, audit notes, session or ticket data. Do not forward upstream drop/forfeit affordances. Recheck recipient identity immediately before sending as PLAY-03 already does.

Engine version and clock revision are independent: a pause can be published without changing cards or invalidating current refs, while a timed-out turn changes engine version and therefore refs. Gateways reconcile both versions and publish only committed state. Exact-checkpoint viewer caching remains reusable; clock updates must not force full replay for every display tick. Lost hints are repaired by durable reconciliation. NOTIFY remains match-ID-only.

The browser interpolates a display estimate using a server sample and its local monotonic clock, clamped at zero. Reaching zero changes the display, never the game. Clock data has explicit ownership/copy validation and is cleared on sign-out, suspension, reconnect and disposal with the viewer state. Resume obtains a fresh authenticated snapshot and clock projection before interaction; restored pending commands keep their original identity. The synthetic harness verifies these behaviors without treating it as approved final game UI.

Only the qualification profile is admitted here; production durations and tournament round rules remain unselected. Manipulated Sandbox rewards stay forbidden. A policy slot is not evidence that its queue or game mode exists.
