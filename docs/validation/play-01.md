Observations for later work (none blocks integration):

- **Sandbox manipulation stays in scope.** Lab advanced-sandbox now refuses the raw manual moves too, which is the right default. Requirements R04.009–R04.017 (construct board states, set lore and damage, pre-populate ink, place cards into zones) remain in the Director's scope. They need dedicated, reward-isolated Sandbox operations later, as ADR0013 already states; this is not a scope reduction.
- **Recovery cost grows with match length.** Every command restores the match by re-executing its whole private transcript inside a worker limited to 5 s and 64 MiB. That is fine for the short synthetic fixture. Restore time for realistic-length matches with real cards is unmeasured, and must be measured before PLAY-03/OPS-01; add snapshot checkpoints if needed.
- **Seeds at rest.** Live private checkpoints, including each match's seed, are stored unencrypted in `match.matches` and readable only by the match role (RUN122). Database backups and exports therefore contain them, so OPS-01 backup/restore and D10 handling must treat backups as secret material.
- **Stale and rejected receipts are final for their command ID.** A client that receives `stale` must send a new command ID, which the runbook documents. The PLAY-03 client protocol must follow this.
- **Correction to the refresh audit.** RUN055 reported the kernel as "895,847 bytes"; that figure counts UTF-16 characters. The file is 895,853 bytes, and PLAY-01 does not change it (RUN124).
