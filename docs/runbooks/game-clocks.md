## Policy and engine ownership

Thinking time is separate from ink. Reuse existing native dynamic settlement, action/pass bonuses, cap and exhausted-player replenishment. The outgoing timed-out player receives125000ms under native150000initial/cap,5000action,60000pass and60000reset values. These are qualification defaults; launch durations are unselected. Successful ordinary actions follow native rules; only the private server timeout-limit path may invoke judge-only forfeitGame with the derived opponent and reason timeout. Players/auditors cannot send it or choose a winner. Main-game expiry validates an ordinary pass; impossible passing rolls back and pauses with no_legal_default. Opening expiry loses immediately. A legal pass may naturally complete the game under existing engine rules.

`createPrivateMatch` optionally accepts a bounded qualification clock policy and a positive captured startTimestamp (zero is native's unset sentinel; untimed zero remains valid). `clock()` returns constructed private native data, not a wire object. `controlClock` accepts only settle/pause/resume/reset. It preserves history/log sequence/card refs, excludes paused intervals and refuses completed controls. Invalid speculative commands revert clock mutation/bonuses. Current timed/untimed private transcript3 and checkpoint envelope2 reconstruct all controls, timeout transitions and exact hashes. Unsupported prior identities fail closed without rewriting saved data. Seeds/private replay remain participants/authorized-auditor only with no delivery endpoint.

## Durable admission and outcomes

Migration0005 adds clock state, short reservations and metadata-only clock events. It is applied to local/test; 0001..0005 remain immutable; append-only0006 admits protocol4 without rewriting rows. Only match-role storage may access them. Backups contain shuffle secrets and require secret handling.

`createClockRepository` is also the primary MatchRepository. Writers lock match then clock and reread current state after both locks; a pre-wait READ COMMITTED snapshot cannot make decisions. `reservePlayer` checks prior receipt/version/pins/deadline. Active-player work commits a bounded lease before expensive proof reconstruction or transition work. Waiting non-concessions are refused without a lease; waiting concessions return an unreserved evaluation for proof/transition outside locks. Exact deadline refuses ordinary active-player admission; either player may still concede before the timeout wins the final fence; an earlier active reservation may complete later within its lease. Final CAS verifies owner, versions, checkpoint and lease, then atomically commits state/clock/receipt/journal/outbox/events. No SQL transaction stays open for engine computation.

Invalid calculations keep the original UTC charge anchor and earn no bonus. `reject` checks authority time under locks: expiry, backward time or missing health commits a safety pause before returning UNAVAILABLE, without applying the calculation or writing an invalid-intent receipt. Wrong owners cannot release another reservation. Timeout identities are disjoint from both participants. Public receipts/hints never contain seeds, checkpoints, reservation capabilities or hidden state.

`activeClockIds(ids)` is a server-only bounded query (at most256IDs) used to reclaim terminal/paused continuity entries. `scan(limit)` rotates fairly through running/processing rows, at most128per query. These bounds are infrastructure controls, not measured50player capacity.

## Health, continuity and recovery

`createClockHealth` serializes DB UTC samples bracketed by process monotonic reads. Defaults: tolerance1000ms, maximum healthy gap15000ms. Failure latches until trusted audited reset/new factory. A locally stalled/unhealthy actor refuses adjudication and emits no idle shared pause: another owner can remain healthy. An owned in-flight reservation that fails remains fenced and safely paused. Healthy actors detect durable shared gaps/dead leases and pause at the last trustworthy charge, excluding the outage. No helper changes host clocks or evidence guards.

Only actual atomic new-row creation immediately enrolls its creator. A new server encountering saved state must observe independent heartbeat/revision progress; it must not manufacture continuity by self-heartbeating after an outage. Known/probe cleanup uses one bounded active-ID query and generation checks, never granting new continuity. `prepareCreation` reserves one of128local enrollment slots before durable create and releases claims in finally; concurrent creation cannot save a row and then fail only because bookkeeping is full. Audited resume also reserves capacity before its final commit. These are process-local operational bounds, not a production concurrency claim.

`createClockRunner` owns one nonoverlapping sweep, default250ms/batch32, bounded backoff to5000ms, and close stops scheduling/drains active work. Root close signals runner and clock service together, drains both, then closes executor/storage. There is no redundant drain alias. Player disconnect/browser suspension grants no time and cannot concede.

Internal `pauseClock`/`resumeClock` require recoveryAuthority approval of auditId, exact engine/clock revisions and independent operation IDs. Retries return original results; changed reuse conflicts. A resume settles only the preserved healthy interval, excludes outage and can explicitly reset a bounded enrolled allowance. No public recovery/login route exists. Unhealthy actor replacement/audited recovery is separate from a client's reconnect.

## Waiting concession commit contract

`commitWaitingConcession(evaluation, command, candidate?, engineClock?)` is an internal server friend, never a public command or capability. Duplicate/hash semantics are unchanged. Its initial evaluation has no SQL write, reservation, pause or clock event. Final match→clock locks require identical state version/private checkpoint/clock fields (only `lastHealthyUtcMs` may advance independently), running phase, waiting actor and no owned lease. The DB sample must remain healthy, non-backward and younger than the configured lease duration; a bad proposal is unavailable without shared mutation. Native refusal writes only invalid_intent; native acceptance must end the game for the other player and commits all durable outputs atomically. Concurrent state/clock revision is stale and cannot overwrite newer work. D13/P060 now accepts either participant's opening concession as a loss, using this same unreserved final fence.

## Current D13 policy and presentation

Policy schema2 requires timeoutLimit integer1..10. Qualification fixtures select3; production values are unselected. Native per-player timeoutCount covers the whole game and never resets, including a player's own pass in negative time. At the threshold the same transition ends as a timeout loss; the first opening expiry does so regardless of the main limit. resetTimeOnSkipMs and native bonuses remain D14 behavior (125s in the150/5/60/60 qualification example). Natural terminal results freeze first. Pauses, audited resume/reset, outages and quarantine do not count.

`timeout({expectedRevision,timestamp,commandId})` is an internal adapter friend with no actor/winner/forfeit field. It records one private transcript3 operation and one logical saved revision, receipt/journal/outbox result even when native pass and forfeit both execute. Native event/reveal state IDs remain native. Replay/restore bind the compiled identity and reject forged histories; previous checkpoint/policy versions fail closed without rewriting them.

Public viewer2 endReason is null while live, otherwise normal_win/concession/timeout. Public clock2 adds timeoutLimit and each player's native timeoutCount, without seed, engine state or reservation fields. live4 is required for new D13 matches; old2/3-only offers refuse rather than receiving new fields. match-client's timeoutWarning and matchResult validate current closed projections and provide qualification display text; countdown estimates cannot adjudicate. WEB-02 owns the actual game UI. Count/limit warnings precede the last main-game timeout; opening always loses at the first expiry, independently of that main limit. Qualification warning callers supply opening=true from the current viewer turn0 so the first expiry is warned too.
