# Viewer privacy operation

Read ADR0014, docs/contracts/viewer.md and docs/validation/play-02.md. Application checks run in the existing Dev Container; one heavy qualification at a time. Preserve credentials, original local/test database data, retained identities and sealed run/change records. Clock investigation is ended; guard unchanged.

Private adapter handles from `createPrivateMatch`/`restorePrivateMatch` now add `project(viewer)` and `resolveIntent(actor,move,input)` to status/submit/checkpoint/dispose. These are server friends, not browser exports. `project` returns a fresh bounded DTO; repeated reads consume no RNG or journal entries. `resolveIntent` maps only current viewer references to internal engine identities and validates the synthetic field profile. Internal submit/checkpoint remain privileged. Qualification replay facade and Lab RPC still expose no private inspection or live persistence. Never route the internal raw-ID submit method directly to a browser.

The durable service adds `view(trustedActor,{matchId})`. It validates request/actor separately, uses participant-restricted repository load, resolves exact retained release and runtime pins, restores in a bounded worker and validates the returned DTO's match/participant/version/end/winner. It does not write a receipt, journal, outbox or checkpoint. Errors are fixed INVALID_REQUEST/FORBIDDEN/PIN_UNAVAILABLE/UNAVAILABLE; unknown matches and outsiders both return FORBIDDEN. `EngineExecutor.project` returns only a validated projection; transition jobs still carry private checkpoints internally. Workers retain existing concurrency2/queue32/deadline5s and64MB old/16MB young/4MB stack limits; stdout/stderr drain without forwarding. Shutdown reaps owned workers.

Changing the compiled adapter/kernel invalidates previous executable identities. Existing old private records are preserved and fail PIN_UNAVAILABLE rather than being silently migrated. No database schema or credential change is needed. Production retention/migration/restore qualification remains later release/operations work.

Run `pnpm test:viewer-privacy` after builds for two independent HTTP/WebSocket client fixture tests over five closed output surfaces and paired hidden worlds. This fixture binds only an owned ephemeral loopback port, reaps sockets/server and implements no product authentication or deployment. `pnpm --filter @lorcana/contracts test`, `pnpm --filter @lorcana/engine-adapter test`, service unit tests and `pnpm test:match-integration` exercise closed codecs, mixed private identities, reveal/expiry/under-card/ink policy, reference binding, journal/RNG invariance and real committed recovery/authorization. Root test includes the wire tests; the existing CI foundation and live-match stages run them. Keep file concurrency1; explicit transactional race tests still run concurrent candidates.

Audit cautions (2026-10-14 UTC, CHG-20261014-005):
- Client commands must enter only through `resolveIntent` with current references. Never expose the raw-identity `submit`.
- A participant's references include the opponent's anonymous backs. Keep any client-visible rejection outcome independent of the hidden card.
- Each `view` restores in a fresh worker by full re-execution: about 0.2 s for a 16-version synthetic game, shared with command capacity (2 active/32 queued). Cache per committed version and rate-limit before clients poll.
- A projection fails closed above 4,096 raw engine events (synthetic play ≈7.2 per move). Measure real-card matches before publication.
