## Interfaces and authority

`createMatchService({repository,releases,executor?,now?})` requires a trusted retained `ReleaseRegistry` with an active built foundation engine and an implemented protocol range within1..2. New matches pin the active maximum; old protocol1 stays distinct. `create({matchId,players})` accepts exactly two distinct bounded ASCII identifiers, captures server time, generates a private cryptographic seed and writes a synthetic non-rewarding match. Existing identity with identical participants/release/engine returns the existing match; conflicting reuse fails. It returns only match/version/release metadata.

`submit(trustedActor,{matchId,commandId,expectedVersion,move,input})` keeps actor authority outside the request body. Plain closed own-data objects, safe unsigned counters, ASCII IDs up to80 characters, moves up to64 characters and copied input are mandatory; the canonical full semantic intent is limited to16KiB. Malformed input fails `INVALID_REQUEST` before durable writes. Participation is checked against storage. `(matchId,actorId,commandId)` and the canonical intent hash identify a receipt: identical retry returns it with `duplicate:true`; altered content/version fails `ID_CONFLICT`. Receipt metadata contains no private checkpoint, seed, game state or logs.

Only `chooseWhoGoesFirst`, `alterHand`, `putCardIntoInkwell`, `playCard`, `quest`, `questWithAll`, `challenge`, `moveCharacterToLocation`, `activateAbility`, `resolveBag`, `resolveEffect`, `passTurn` and `concede` may reach the kernel. The same browser-safe policy guards Lab. Every manual/debug move, `forfeitGame`, unimplemented server-only `sing`/`singTogether` and unknown/prototype names is refused. Advanced Sandbox does not gain a generic debug bypass; future manipulation operations need explicit authority and reward isolation.

## Audit notes — 2026-10-13 UTC

The independent audit (CHG-20261013-006) adds three operating cautions:
- **Command IDs:** a `stale`, `forbidden` or `invalid_intent` receipt is final for its command ID. Callers resubmit a new intent under a new ID, and retry only the identical intent under the old one.
- **Seeds in storage and backups:** private checkpoints in `match.matches` contain each live match's seed. Treat database dumps, backups and restore copies of the match schema as secret material, and keep them away from logs, tickets and shared storage.
- **Restore cost:** each command restores the match by re-executing its full transcript within the 5-second worker limit. Measure that cost on realistic-length matches before raising command limits or admitting real cards.
