# ADR0016 — Durable integration of native engine thinking-time clocks

Status: Director-approved design and plan; implemented and locally verified for synthetic scope; Director audit/publication separate. Tasks PLAY-04/DOC-01/02; requirements R02.030/.031, R29.006/.007, R30.010. Policy D12 (as superseded by D13/D14 for player expiry) and the [approved design](../plans/2026-10-15-play-04-design.md) record authority and alternatives. Acceptance is governed by [current validation](../validation/play-04.md).

Reuse the pinned runtime's existing dynamic clock rather than duplicate its arithmetic or change ink/turn rules. Add only the project-owned bridge and server adapter integration, then durable database anchors/reservations, validated server-only legal timeout passes, audited recovery and distinct live3/public estimates. D13 authorizes a player timeout loss at the native whole-game count limit and immediately during opening. An impossible main-game legal default or unreliable infrastructure pauses without charging an incident. Ordinary player disconnect grants no time.

The source already contains dynamic/chess/priority clocks and helpers, but the prior bridge used mode none. Existing raw clock tests are evidence for the selected runtime, not evidence for durable multiplayer scheduling. The private timeout handler alone may invoke the existing judge-only forfeitGame, deriving the opponent and literal reason timeout; player and audit interfaces cannot invoke it. Private clock controls must preserve game history and deterministic replay without adding a player/debug path.

The bridge/adapter, migration0005/fenced clock repository, native worker/service/runner/audited recovery and distinct live3/client estimate source are implemented. Current full-source/database/browser/clean/canonical proofs and review dispositions are recorded in validation. The time sampler serializes queries to prevent reordered responses manufacturing clock reversal. New-row continuity uses an atomic creation outcome; joining existing rows requires independently observed progress rather than self-heartbeating an outage. Clocked startTimestamp0 is refused because native0 means unset; this restriction changes no upstream code and leaves untimed0 supported.

Only sourced P060 repairs the opening validMoves lists; no other upstream/core rule change is authorized. Production durations/counts, host repair, provider/deployment, auth/admission and official/card/reward/device/production acceptance remain separate. Preserve every failed receipt. Follow the approved design for deadline fairness, namespace fencing, continuity and complete verification obligations.

## Unreserved waiting concessions — 2026-10-16 UTC

Residual R1 requires a separate admission path for the waiting participant: a refused opening concession must not own the active player's timed lease. Compared with keeping the lease, optimistic evaluation prevents even deliberately delayed waiting engine work from fencing active decisions. Compared with allowing opening `forfeitGame`, it preserves native rules and the unresolved Director opening-leave policy. Compared with dropping server-busy retries from the browser counter, it fixes the source of contention without changing unrelated retry behavior.

The short admission returns an unreserved snapshot and sampled logical timestamp. Engine proof/transition runs outside transactions. A short match→clock locked reread then writes only a refusal receipt, or atomically commits a native terminal concession, iff state/archive/clock are unchanged (independent heartbeat health progress excepted), no reservation exists, and sample age/health are safe. Concurrent adjudication makes the result stale; a waiting evaluation never owns pause/release authority. Bare timed writes remain fenced. R02.030/.031, R29.006/.007 and R30.010 are affected infrastructure prerequisites, not full product acceptance. RED004 and the validation's fresh complete suites supply comparative evidence. No migration, native rule, wire or deployment decision changes.
